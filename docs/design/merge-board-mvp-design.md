## Karpathy 자가점검

- 사고: PASS — 사용자 확정 요구와 기존 코드를 대조하고 씨앗팩 입력·에너지·오프라인 회복·저장 호환성을 구분했다.
- 단순함: PASS — 보드 하나, 합성 3단계, 씨앗팩 하나, 고정 주문 3개를 유지한다.
- 외과적 변경: PASS — 기존 Model / Controller / View / SaveService 안에서 생성 경로와 저장 데이터만 확장한다.
- 목표 주도 실행: PASS — 생성·소모·회복 경계값, 실제 입력과 재시작 검증을 커밋 단위에 연결했다.

## 구현 목표와 제외 범위

기준은 [MVP_SPEC.md](../../MVP_SPEC.md)와 사용자가 추가 확정한 요구사항이다. 기존 MVP는 구현된 상태다. 이번에는 별도 `씨앗 만들기` 버튼을 보드 위 씨앗팩으로 바꾸고 2초 생성 쿨타임을 에너지로 대체한다. 이 설계 문서를 먼저 단독 커밋하고, 구현 전에 MVP_SPEC.md의 생성기·UI·저장·완료 조건을 동기화한다.

- 씨앗팩 클릭으로 가까운 빈 칸에 씨앗 하나를 만든다. 생성 재사용 대기시간은 없다.
- 초기·최대 에너지는 100이며 생성 성공마다 1을 소모한다.
- 에너지가 100 미만이면 120초마다 1씩 회복한다. 사용자 확정에 따라 종료 중에도 회복하며 최대 100이다.
- uGUI와 Animator를 유지한다. 기존 합성·Get 제출·총 230코인 보상은 바꾸지 않는다.

서버, 로그인, 결제, 광고, 상점, 인벤토리, 튜토리얼, 이벤트, 추가 합성 체인·주문, 에너지 구매·광고 충전, 생성기 업그레이드, 고품질 아트·사운드, 모바일 실기기 대응은 제외한다. 로컬 시계 조작 방지 시스템은 추가하지 않는다.

## 보드·아이템·주문·저장 데이터 모델

| 모델 | 데이터와 불변 조건 |
| --- | --- |
| BoardModel | 7열 × 9행, 63칸. 좌측 상단 (0, 0), 인덱스 = 행 × 7 + 열. 각 칸은 빈 칸 또는 아이템 하나. |
| ItemStage | 기존 Empty=0, Seed=1, Sprout=2, Flower=3을 보존하고 SeedPack=4를 추가한다. SeedPack은 합성 단계가 아니며 생성·합성·주문 소비 대상이 아니다. |
| GameState | Board, Orders, Coins에 Energy(0~100), EnergyRecoveryAnchorUtcSeconds를 추가한다. 초기 코인 0, 에너지 100, 회복 기준 시각 0. |
| OrderModel | Order01: 새싹 1개/20코인, Order02: 꽃 1개/60코인, Order03: 꽃 2개/150코인. 완료 주문 재제출 금지. |
| SaveData | version=2, cells[63], coins, orderIds[3], completedOrders[3], energy, energyRecoveryAnchorUtcSeconds. 저장 호환성 정책 확정 시 필요한 지급 대기 상태만 추가한다. |

신규 게임은 첫 행 씨앗 4개를 유지하고 중앙 (3, 4), 인덱스 31에 씨앗팩 하나를 추가하는 안이다. 씨앗팩은 빈 칸으로 이동할 수 있지만 합성·소모·복제되지 않는다. 이 배치와 이동 정책은 구현 전에 알릴 가정이다. Model은 MonoBehaviour·UI·파일 접근에 의존하지 않는다. 식별자는 영어, 주석과 필요한 XML summary는 한국어로 작성한다.

회복 기준 시각은 UTC Unix 초다. 최대 에너지에서는 0으로 두어 시간을 적립하지 않는다. 100에서 첫 소모로 99가 될 때 현재 시각을 기록한다. 회복 중 추가 소모는 기준 시각을 다시 시작하지 않는다.

기존 파일을 찾기 위해 저장 파일 이름 `merge-board-v1.json`은 유지하고 내부 version으로 구분한다. 유효한 버전 1의 보드·코인·주문은 보존하고 에너지 100을 부여한다. 빈 칸이 있으면 중앙에서 체비쇼프 거리가 가장 가까운 빈 칸에 씨앗팩 하나를 배치한다.

**구버전 보드가 가득 찬 경우는 미확정이다.** 기존 아이템을 임의 삭제하거나 저장을 초기화하지 않는다. 권장안은 지급을 보류하고 합성·주문으로 첫 빈 칸이 생길 때 배치하는 것이다. 이 경우 보류 상태도 저장하며, 빈 칸을 만들 수 없는 구버전 상태의 처리까지 사용자 확인이 필요하다. 정책 확정 전 저장 마이그레이션 구현은 시작하지 않는다.

버전 2는 기존 배열·단계·주문 ID·코인 합계 외에 에너지 범위, 시각 범위, 씨앗팩 개수와 지급 대기 상태의 일관성을 검증한다. 누락·손상·미지원 버전은 기본 상태로 시작한다. 기존 임시 파일 작성 후 교체, 실패 시 이전 파일 보존과 안내를 유지한다. 저장 실패로 현재 플레이 상태를 되돌리지 않는다.

## 드래그 이동, 합성, 주문 제출, 저장/복원의 상태 흐름

| 입력·시점 | 판정과 상태 전이 | 표시·저장 |
| --- | --- | --- |
| 드래그 시작·취소 | 원본 칸은 유지하고 표시만 움직인다. 취소 시 모델 변경 없이 복귀한다. | 드래그 동안 생성·Get 입력을 막는다. 드래그가 끝난 포인터를 클릭으로 중복 처리하지 않는다. |
| 빈 칸 드롭 | 씨앗팩을 포함한 아이템을 목적지로 이동하고 원본을 비운다. | 즉시 저장하고 보드를 갱신한다. |
| 같은 단계 드롭 | Seed+Seed 또는 Sprout+Sprout만 다음 단계로 합성한다. | 원본 제거·결과 배치 후 저장하고 Animator 확대·단계명을 표시한다. |
| 잘못된 드롭 | 보드 밖, 다른 단계, Flower끼리, 씨앗팩과 점유 칸, 빈 원본은 거절한다. 같은 칸은 변화가 없다. | 원위치·안내를 표시한다. 명령에 의한 저장·에너지 소모는 없다. |
| 씨앗팩 클릭 | 씨앗팩 여부를 확인하고 자연 회복 반영 후 에너지와 빈 칸을 검사한다. 최근접 빈 칸에 Seed를 배치하고 에너지 1을 차감한다. | 보드와 에너지를 함께 즉시 저장하고 씨앗팩 Click Animator를 재생한다. 연속 클릭도 성공당 정확히 1을 차감한다. |
| 생성 거절 | 빈 칸 없음 또는 에너지 0이면 생성하지 않는다. | 각각 `보드에 빈 칸이 없습니다.`, `에너지가 부족합니다.`를 표시한다. 자연 회복과 별개로 생성 실패 자체는 에너지·회복 기준을 변경하지 않는다. |
| 주문 Get 클릭 | 미완료·요구 수량을 재검사하고 작은 칸 인덱스부터 필요한 아이템을 함께 제거한다. 완료·보상을 한 번에 적용한다. | 즉시 저장한 뒤 소비 위치에서 주문 슬롯으로 Animator 비행, 완료 표시와 +코인 텍스트를 표시한다. 애니메이션 콜백에서 보상하지 않는다. |
| 실행 중·복귀 | Controller에 UTC 시각을 전달하여 지난 120초 구간 수만큼 회복한다. | 실제 회복·기준 시각 보정 시 저장한다. HUD 카운트다운 표시는 저장하지 않는다. |
| 게임 시작 | 저장 검증·구버전 변환 후 같은 회복 계산을 수행한다. | 오프라인 회복 반영 상태를 저장하고 표시한다. 재시작만으로 타이머를 초기화하지 않는다. |

생성 위치는 체비쇼프 거리 `max(abs(columnDifference), abs(rowDifference))`로 결정한다. 대각선을 포함한 8방향의 가까운 빈 칸부터 선택하고 동률이면 작은 보드 인덱스를 선택한다. 63칸 단일 순회로 충분하며 경로 탐색·전략 인터페이스·무작위 선택은 추가하지 않는다. 사용자 요청으로 참조 프로젝트의 DefaultGeneratorPlacementStrategy와 MergeTileManager.FindNearestEmptyTile에서 이 배치 규칙만 확인했다. 코드·클래스 구조·패키지는 가져오지 않는다.

회복 계산은 `elapsed = max(0, now - anchor)`, `recovered = min(100 - energy, floor(elapsed / 120))`다. 100 미만이면 기준 시각에 회복 수량 × 120초를 더해 남은 초를 보존한다. 100이면 기준 시각을 0으로 지워 초과 시간을 버린다. 50에서 250초 경과 시 52, 다음 회복까지 110초다. 98에서 250초 경과 시 100이며 이후 소모부터 새 120초가 시작된다.

UTC 시각이 저장 기준보다 과거이면 회복량 0, 기준 시각을 현재로 보정하는 안이다. 잘못된 입력 시각은 거절한다. 장기 미접속도 회복 상한을 먼저 적용해 오버플로를 막는다. 이는 음수 회복·장기간 정체 방어이며 시계 조작 방지를 보장하지 않는다.

## View / Controller / Model / SaveService 책임 분리

| 계층 | 책임 |
| --- | --- |
| View | uGUI 클릭·드래그 전달, 아이템·코인·에너지·남은 회복 시간·안내 표시, Animator 재생. 생성·차감·회복·저장 규칙은 처리하지 않는다. |
| Controller | 생성기 확인, 최근접 빈 칸, 이동·합성·주문·보상, 소모·회복 계산, 변경 직후 저장 요청. Unity UI 타입에 의존하지 않는다. |
| Model | 보드·아이템·주문·코인·에너지·회복 기준 시각과 조회 상태. |
| SaveService | JSON 읽기·쓰기, 포맷 검증·변환, 실패 결과 전달. 시간에 따른 회복 규칙은 Controller에 둔다. |

Bootstrap이 UTC 시각을 전달하고 View와 Controller를 연결한다. 기존 uGUI 장면을 Inspector에서 편집 가능하게 유지한다. 별도 생성 버튼을 제거하고 상단 HUD에 `에너지 99/100`과 다음 회복 `01:59`를 표시한다. 최대치에는 타이머 대신 `최대`를 표시한다. 상단 HUD·가로 주문 영역·중앙/하단 보드 배치는 유지하고 관련 없는 UI는 재배치하지 않는다.

커밋 전 git status, staged diff, diff --check, 캐시 미포함, .meta 짝을 확인한다. 각 커밋 후 git status가 깨끗한지 확인한다. 사용자 변경은 보존하며 별도 승인 없이 포함하지 않는다. 실패한 검증을 통과로 기록하거나 미완료 기능을 완료로 보고하지 않는다.

## 주요 가정과 불확실성

- 확정: uGUI, 영어 식별자와 필요한 한국어 summary, Animator, 보드 씨앗팩 클릭 생성, 생성 쿨타임 제거, 초기·최대 에너지 100, 성공당 -1, 2분당 +1, 종료 중 회복.
- 구현 전 알릴 가정: 씨앗팩 하나를 중앙 31번 칸에 추가하고 빈 칸으로 이동 가능하게 하며 합성·주문 대상에서는 제외한다. 기존 씨앗 4개는 유지한다.
- 참조는 기존 UI 배치와 사용자 요청한 체비쇼프 최근접 빈 칸 규칙 확인으로 한정한다. 아키텍처·코드를 복사하지 않는다.
- 미확정: 가득 찬 버전 1 저장에 씨앗팩을 넣는 방법. 기존 아이템을 지우지 않는 지급 보류안을 제안하되 빈 칸을 만들 수 없는 상태까지 사용자 확인이 필요하다.
- 로컬 UTC 시계의 과거 변경은 무회복·기준 보정, 미래 변경은 최대 100 회복으로 제한하는 안이다. 시계 조작 자체를 방지하지 않는다.
- 이 문서는 설계이며 변경 기능의 구현·검증 완료를 뜻하지 않는다. MVP_SPEC.md의 기존 쿨타임·무작위·버튼 설명은 다음 문서 단위에서 동기화한다.
